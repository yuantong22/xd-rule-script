# 脚本规则工作台 — 需求文档（PRD）

> 版本：v0.2（需求梳理稿，待评审）
> 日期：2026-09-01

## 1. 背景与目标

决策引擎的规则使用 Groovy 脚本编写。目前写规则、验规则、试规则缺少顺手的工具。
本项目做一个 **Web 版"脚本规则工作台"**，解决三件事：

1. **写**：提供脚本编辑器，支持 AI 对话辅助编写
2. **验**：一键校验脚本（语法校验 + 提取占位符 + 大模型审查语义问题）
3. **跑**：给占位符填值，真实执行脚本，查看返回值

## 2. 范围与边界

| 项 | 说明 |
|---|---|
| 脚本语言 | **仅 Groovy**（Python 不做） |
| 占位符语法 | `${变量名}`，例如 `${age}` |
| 用户体系 | 无，单用户工具，不做登录权限 |
| 部署形态 | 前后端分离开发，本机运行为主 |

## 3. 术语

- **规则**：一段 Groovy 脚本，决策引擎的最小执行单元，有返回值
- **占位符**：脚本中用 `${变量名}` 标记的输入变量，运行前需赋值
- **会话**：与 AI 大模型的一次对话（有独立记忆），一条规则固定对应一个会话
- **测试用例**：一组占位符填值的快照，可保存、可一键回填重跑

规则列表页 ──点击规则──▶ 规则工作台页（编辑 + 校验 + 运行 + AI 对话）
```

| 搜索 | 按规则名称模糊搜索 |

### 4.3 规则工作台页

**页面布局**（文字版线框，UI 细节可继续脑暴）：

```
┌──────────────────────────────────────────────┐
│ 规则名称                          [校验] [运行] │
├───────────────────────────┬──────────────────┤
│                           │                  │

#### 4.3.1 脚本编辑

- 编辑器带 Groovy 语法高亮、行号（选型：CodeMirror 6）
- 脚本内容需手动保存（保存按钮 / Ctrl+S），保存即更新规则列表中的数据
- **注意**：校验、运行、AI 对话、AI 审查，用的都是**编辑器里的当前内容**（含未保存的修改），不是数据库里的已保存版本

#### 4.3.2 校验（核心流程，同步）

两个按钮：**[校验]** 和 **[运行]**。规则：**必须校验全部完成且语法通过，运行按钮才可点击**。

点击 [校验] 后依次发生（**全部同步等待完成后才返回**）：

1. **语法校验**（毫秒级）
   - 把占位符按所在声明的类型替换为假值后编译（如 `int age = ${age}` → 用 `0` 替换）
   - 失败 → 立即返回错误**行号 + 原因**，编辑器中该行标红，运行按钮保持锁定
2. **提取占位符列表**（毫秒级）
   - 从脚本中识别所有 `${变量名}`，并根据变量声明语句解析出类型（`int`/`long`/`double`/`boolean`/`String` 等）
3. **大模型 CR**（同步等待，约数秒到十几秒，前端展示"AI 审查中…"加载状态）
   - 把脚本发给大模型审查：语义错误、逻辑漏洞、潜在空指针等
   - 结果展示为"AI 审查"卡片
   - 若大模型给出修改后的完整脚本，卡片上提供 **[应用到编辑器]** 一键替换
4. **返回并解锁运行**
   - 语法通过 → 解锁运行按钮，同时展示占位符列表和 AI 审查卡片
   - **说明**：CR 是建议性质，即使 CR 指出问题也不强制阻断运行，只要语法通过 + CR 已返回即解锁

**关键规则**：脚本内容一旦被修改，校验结果作废，运行按钮重新锁定，必须重新校验。

#### 4.3.3 运行

- 校验通过后，下方出现**占位符填值表单**，按类型渲染控件：
  - `int` / `long` / `double` → 数字输入框，前端校验格式
  - `boolean` → true/false 下拉
  - `String` → 文本框
  - 前端校验不通过不允许提交
- 点击 [运行] → 后端在 **Groovy 沙箱**内执行 → 展示**返回值**
- 执行超过 **5 秒**自动中断并提示超时
- **测试用例**：
  - [保存为用例]：把当前一组填值命名保存
  - 用例下拉列表：选中后一键回填所有输入框，再点运行即可重跑
  - 可删除用例

#### 4.3.4 AI 对话面板

- **一条规则固定一个会话**（规则创建时自动建立，无会话列表、不能新建/删除会话）
- 每次发消息，自动把**当前编辑器中的脚本内容**一并作为上下文发给大模型
- **流式输出**（打字机效果）
- 大模型回复中若包含完整脚本代码块，提供 **[应用到编辑器]** 按钮
- [清空对话]：清除该会话的记忆和历史消息
- 打开页面时加载历史消息回显

## 5. 安全与约束：Groovy 沙箱

服务端执行用户脚本有风险，必须加防护：

| 措施 | 说明 |
|---|---|
| AST 黑名单 | 编译期禁止：`import` 语句、`java.io.*`、`java.net.*`、`System.exit`、`Runtime`、`Thread`、反射、文件/网络操作 |
| 执行超时 | 5 秒强制中断 |
| 错误兜底 | 脚本抛异常时，向前端返回可读的错误信息而非原始堆栈 |

## 6. 数据模型（MySQL）

| 表 | 字段 | 说明 |
|---|---|---|
| rule | id, name, description, script_content, created_at, updated_at | 规则 |
| conversation | id, rule_id(唯一), title, created_at, updated_at | 会话，与规则一对一，创建规则时自动生成 |
| message | id, conversation_id, role(user/assistant), content, created_at | 消息，**除 ChatMemory 外同步落库**，用于历史回显 |
| test_case | id, rule_id, name, params_json, created_at | 占位符填值快照 |

说明：
- ChatMemory（内存）负责运行时对话上下文；message 表负责持久化历史，两者都保留
- 删规则时级联删除 conversation、message、test_case

## 7. 技术方案

| 层 | 选型 |
|---|---|
| 前端 | Vue 3 + Vite 打包（Node.js 构建）、CodeMirror 6 编辑器、Element Plus 组件库 |
| 后端 | JDK 17 + Spring Boot 3.4 + Spring AI Alibaba（对接阿里百炼 DashScope）+ Spring Data JPA |
| 数据库 | MySQL 8 |
| 大模型 | 对话和 CR 统一用 qwen-plus，模型名配置化，API Key 后补 |
| 对话记忆 | Spring AI 内置 ChatMemory（InMemory），按会话隔离；消息同步落 MySQL |
| 脚本引擎 | Groovy 4（JVM 原生，GroovyShell + SecureASTCustomizer） |
| 流式输出 | SSE（Server-Sent Events） |

## 8. 接口设计（全部 POST，按接口名区分）

```
规则：
  POST /api/rule/list          列表（name 模糊搜索、分页）
  POST /api/rule/create        新建（name、description，自动建会话）
  POST /api/rule/detail        详情（ruleId）
  POST /api/rule/update        更新（名称/描述/脚本内容）
  POST /api/rule/delete        删除（级联删除会话、消息、测试用例）

校验与运行：
  POST /api/rule/validate      校验（入参：脚本内容；同步返回：语法结果、
                               错误信息、占位符列表、AI CR 结果）
  POST /api/rule/run           运行（入参：脚本内容、占位符键值对；返回：返回值）

AI 对话（一规则一会话）：
  POST /api/chat/history       历史消息（ruleId）
  POST /api/chat/send          发消息（ruleId + 消息 + 当前脚本内容，SSE 流式返回）
  POST /api/chat/clear         清空记忆和历史消息（ruleId）

测试用例：
  POST /api/testcase/list      用例列表（ruleId）
  POST /api/testcase/save      保存用例（ruleId、name、参数键值对）
  POST /api/testcase/delete    删除用例（testCaseId）
```
